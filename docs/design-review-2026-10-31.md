# 程序设计与实现检查

检查基准：`86c5000f95e1e804108049276e7195fc85583797` 的 Rust 后端、Flutter 界面与构建脚本。以下问题来自代码审查；涉及网络异常、磁盘写入失败和资源耗尽的场景尚未进行故障注入。严重程度按照远程操作可靠性、文件完整性和资源占用评估。

## 高优先级

### 1. 远程结果删除前缺少服务器记录确认

- 代码：[remote.rs](../src/remote.rs#L78-L109)。认领调用时会检查 PATCH 返回的记录；提交结果和重新发送 outbox 时只检查 HTTP 是否成功，随后删除本地结果文件。
- 触发条件：提交结果时，服务器记录已经不再满足 `status=executing` 条件，PATCH 返回成功但没有更新任何记录。
- 影响：本地结果副本被删除，客户端缺少可用于核实或重新提交的结果。是否在实际服务上形成结果丢失，取决于服务端调用状态的变化。
- 建议：核对返回记录的调用编号、完成状态与结果；没有匹配记录时查询最终状态，再决定保留或删除 outbox。已经执行过的命令需要保留结果，避免重新执行副作用。

### 2. 多文件读取与文档处理缺少累计资源预算

- 代码：[tools.rs](../src/tools.rs#L128-L135)、[documents.rs](../src/documents.rs#L14-L64)、[documents.rs](../src/documents.rs#L141-L149)、[documents.rs](../src/documents.rs#L183-L220)。
- 单文件、单张图片和文档源文件有部分限制，但 `read_multiple_files` 没有路径数量或累计响应字节限制；Markdown 附件缺少累计限制；DOCX 编辑会完整读取相关 XML，XLSX 在限制返回单元格数量前已经载入工作簿。
- 触发条件：一次读取大量文件，或者处理包含大量附件、解压后体积很大或结构复杂的文档。
- 影响：后台响应体、文档子进程内存和临时文件占用明显增加。空闲内存低于 50 MiB，无法证明执行这些任务时也有资源上限。
- 建议：分别限制单次调用和全部并发调用的输入、解压内容、附件、输出累计字节；批量读取提供分页；文档子进程还需要运行时间和资源限制。

### 3. 部分文件写入直接覆盖原文件

- 代码：[tools.rs](../src/tools.rs#L136-L145)、[documents.rs](../src/documents.rs#L110-L123)。普通文本覆盖写入先截断原文件，DOCX 创建直接使用 `File::create(path)`。
- 触发条件：覆盖现有文件时磁盘写满、进程中断或后续写入失败。
- 影响：原文件可能变为空文件或只保留部分内容。其他文档路径虽然使用临时文件，失败时仍可能留下临时文件。
- 建议：覆盖操作使用目标目录中的临时文件，写入成功后通过现有原子替换库提交；失败时清理临时文件。追加写入单独定义失败后的行为。

## 中优先级

### 4. 搜索结果缺少磁盘总量限制，逐条执行刷新

- 代码：[search.rs](../src/search.rs#L19-L26)、[search.rs](../src/search.rs#L53-L74)。搜索限制结果条数，但没有累计字节限制，每条结果都会 `flush`；完成文件的过期清理在下一次启动搜索时执行。
- 触发条件：在大量文件中搜索命中很长的文本行，或者同时运行多个结果很多的搜索。
- 影响：结果文件可以持续增长，逐条刷新增加写入调用；搜索结束后如果没有下一次搜索，过期文件继续占用磁盘。`flush` 的频率不能直接等同于物理磁盘写入次数。
- 建议：增加每个搜索及所有搜索的累计字节限制，按大小或时间批量刷新，并在运行期间和退出时执行过期清理。

### 5. 保存设置总会重连，保存失败可能让远程保持停止

- 代码：[control.rs](../src/control.rs#L25-L31)、[app.rs](../src/app.rs#L237-L244)。处理设置更新时先停止连接，再写入启动项和设置，最后重新连接。
- 触发条件：在线时保存任意设置；或者停止连接后，原生启动项更新、设置文件保存发生错误。
- 影响：修改设备名称等设置也产生断线窗口；后续步骤失败时不会重新启动原有连接。启动项修改成功而设置文件写入失败，还可能使系统启动项与保存设置不一致。
- 建议：按设置是否影响当前连接决定是否重连；先完成可能失败的验证与持久化，并为跨文件、系统启动项的更新定义一致的提交和失败恢复过程。

### 6. 停止、退出与请求读取缺少完整的取消边界

- 代码：[app.rs](../src/app.rs#L197-L205)、[remote.rs](../src/remote.rs#L299)、[remote.rs](../src/remote.rs#L12-L18)、[api.dart](../desktop/lib/api.dart#L25-L36)。
- 远程连接退出会等待已经执行的工具任务。通用 HTTP 客户端只有连接超时，URL 读取可持续等待响应；Flutter 请求只对收到响应头设置超时，读取整个响应体没有同一截止时间。
- 触发条件：工具正在等待慢速网络响应或耗时文档处理时，用户停止连接、保存设置或退出。
- 影响：操作可能长时间等待，界面持续忙碌。命令执行是否应继续、结果如何保存，目前没有贯穿各层的取消约定。
- 建议：区分停止接收新调用、取消可取消任务和等待已有任务完成；让网络、文档子进程与管理接口共享有界截止时间，并保留已产生的结果。

### 7. 托盘初始化失败会绕过统一清理

- 代码：[main.rs](../src/main.rs#L113-L127)、[linux_tray.rs](../src/linux_tray.rs#L56-L57)、[platform.rs](../src/platform.rs#L188-L189)。控制服务已经启动后，托盘初始化错误可以直接返回；后面的关闭连接和删除 `control.json` 不会执行。
- 触发条件：Linux 的状态栏服务不可用，或原生托盘构造失败。
- 影响：启动失败后可能遗留失效的管理接口描述文件，不能通过正常的清理流程收回已经启动的工作。
- 建议：让托盘启动失败进入统一清理路径；原生构造错误返回明确错误，并在退出前完成后台与描述文件清理。

## 设计边界与验证覆盖

### 8. 文件目录限制不能约束终端命令

- 代码：[tools.rs](../src/tools.rs#L176-L182)、[tools.rs](../src/tools.rs#L218-L232)、[terminal.rs](../src/terminal.rs#L74-L85)。`allowedDirectories` 用于原生文件工具，终端直接执行系统 shell；`blockedCommands` 按空白分词匹配，不能覆盖所有 shell 表达方式。
- 这是当前授权设备完整远程控制能力的边界，Android 文档也明确说明这些设置不提供安全隔离。目录检查与文件打开之间还存在并发修改符号链接的时间窗口。
- 如果用户需要将远程调用限制在特定目录，仅靠这些设置不能满足要求；需要操作系统权限隔离，以及基于已验证目录句柄的文件操作。

### 9. CI 没有覆盖 Windows、Linux 安装后的全部行为

- 代码：[tray_e2e.py](../scripts/tray_e2e.py#L36-L39)、[package.py](../scripts/package.py#L94-L115)、[build.yml](../.github/workflows/build.yml)。Windows、Linux 的托盘 E2E 从暂存目录运行程序，没有安装生成的 NSIS 或 DEB 包后再执行验证。
- 影响：当前 CI 通过能证明程序与打包步骤成功，安装目录、快捷方式和卸载清理仍可能出现独立问题。已有 Windows 实际部署证据覆盖了当时安装和运行，后续安装器修改仍缺少自动回归验证。
- 建议：在隔离环境中安装产物，执行实际启动、GUI 关闭与重新打开、启动项检查以及卸载清理，并保留安装后的验证记录。

### 10. 调用列表缺少可持续追查的信息

- 代码：[app.rs](../src/app.rs#L153-L173)、[tools.rs](../src/tools.rs#L61-L64)、[main.dart](../desktop/lib/main.dart)。界面使用内存中的最近事件，后台重启后从空列表开始；磁盘历史另有读取路径。记录只含工具名、完成时间、耗时和成功标记。
- 影响：后台重启后界面看不到之前的调用；同名命令难以区分，失败记录缺少可查看的错误摘要，也无法按调用编号关联远程结果。
- 建议：从有上限的持久历史恢复界面列表，增加调用编号和经过脱敏的错误摘要，并支持筛选与详情。原始命令和凭证内容不应直接进入列表记录。

## 时间显示

调用记录继续由 Rust 保存 UTC。Flutter 使用 Dart 的 [`DateTime.parse`](https://api.dart.dev/dart-core/DateTime/parse.html) 和 [`toLocal`](https://api.dart.dev/dart-core/DateTime/toLocal.html)，以界面进程所在设备的系统时区转换，偏移量取调用发生时的 [`timeZoneOffset`](https://api.dart.dev/dart-core/DateTime/timeZoneOffset.html)。显示格式为 `完成于 yyyy-MM-dd HH:mm:ss.SSS UTC±HH:mm`。

真实记录验证入口为 `scripts/live_call_time_e2e.py`，使用独立的 Python 日期实现计算预期值，启动与生产界面使用相同代码的 Flutter 程序，检查真实 Rust 后台记录在界面中的文本；不会写入调用记录或替换管理接口响应。
